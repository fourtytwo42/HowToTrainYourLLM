## Overview

The **Model Workshop** is a locally-hosted dashboard that lets you:

1. **Pull** Llama 3.1 (8B) variants via Ollama
2. **Upload** your own JSONL training data (prompt ↔ completion pairs)
3. **Configure** hyperparameters (batch size, LoRA rank, quantization, early-stop)
4. **Train** a LoRA-augmented, quantized model on your RTX 3090
5. **Monitor** logs, GPU utilization, and receive notifications
6. **Test** the newly trained model with ad-hoc prompts
7. **Manage** presets, prompt templates, and theme (light/dark)

Everything runs locally: React frontend, Node API + BullMQ queue, Python LoRA training, and Ollama for inference.

## Prerequisites

* **OS:** Linux/macOS/Windows WSL
* **GPU:** NVIDIA RTX 3090 (24 GB VRAM)
* **Docker (recommended)** for isolation of Python training
* **Node.js** ≥ 18.16.1 (LTS)
* **Python** ≥ 3.10.12
* **Redis** ≥ 6.2 (local or Docker)
* **Ollama CLI** ≥ 0.4.0 (for `pull`, `run`, `create`)

### Key Pages & Components

1. **`ModelSelector.tsx`**

   * Dropdown of `GET /api/models`
   * Displays context & size badges
   * Refresh & delete icons

2. **`DataUploader.tsx`**

   * Uses `<input type="file" accept=".jsonl" />` + drag-and-drop
   * Validates with AJV JSON Schema:

     ```jsonc
     {
       "type": "array",
       "items": {
         "type": "object",
         "properties": {
           "prompt": { "type": "string" },
           "completion": { "type": "string" }
         },
         "required": ["prompt","completion"]
       }
     }
     ```
   * “Replace vs Append” radio

3. **`HyperparamForm.tsx`**

   * Built with React Hook Form + Zod schema
   * Controls: batchSize, epochs, lr, gradAccum, loraRank/α, dropout, quantization, earlyStop settings

4. **`LogsViewer.tsx`**

   * Connects to Socket.IO `/logs-room`
   * Filters INFO/WARN/ERROR, search box, auto-scroll toggle

5. **`TestConsole.tsx`**

   * Textarea + sliders (temp, maxTokens)
   * Calls `POST /api/jobs/:id/test` → streams response

6. **`ThemeToggle.tsx`**

   * Toggles `document.documentElement.classList` between `dark`/light
   * Stores choice in localStorage

### Validation & State Management

* **React Query** caches all GET endpoints (models, presets).
* **Optimistic updates** for preset creation/deletion.
* **AJV** re-validates JSONL on the server to prevent bad data in the queue.
* **Toast Notifications** (react-toastify) for success/failure of pull/train/test jobs.

### API Routes

* **`GET /api/models`** — list local Ollama models (`ollama list --json`)
* **`POST /api/models/pull`** — enqueue a pull job
* **`POST /api/data/upload`** — AJV validate & save JSONL to `data/raw/`
* **`POST /api/jobs/train`** — enqueue a BullMQ “train” job with hyperparams+flags
* **`GET /api/jobs/:id/logs`** — fetch past logs
* **`POST /api/jobs/:id/test`** — run `ollama run` against trained model

### Job Queue & Worker

* **BullMQ**

  ```ts
  // queue/index.ts
  import { Queue, Worker, QueueEvents } from 'bullmq';
  export const trainQueue = new Queue('train', { connection: { host:'localhost', port:6379 } });
  export const worker = new Worker('train', async job => {
    // spawn Python and llama.cpp commands, stream to logs
  });
  ```
* **Worker Responsibilities**

  1. Spawn `python train.py --data <file> --out <dir> --...`
  2. Upon success, spawn `python merge_quantize.py ...`
  3. Run `ollama create custom-<job.id> -f Modelfile`
  4. Emit progress via Socket.IO to front-end

### GPU Monitoring

* **`gpuMonitor.ts`**

  ```ts
  import nvsmi from 'node-nvidia-smi';
  export async function getGpuStats() {
    const data = await nvsmi();
    // parse for VRAM used/total, utilization, temperature
    return {
      vramUsed: data.memory.used,
      vramTotal: data.memory.total,
      utilization: data.gpu,
      temperature: data.temperature.gpu,
    };
  }
  ```
* Poll every 2 s and emit via Socket.IO to update the header widget.

### LoRA Fine-Tuning (`train.py`)

```python
import argparse, os
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, Trainer, TrainingArguments
from peft import LoraConfig, get_peft_model
from datasets import load_dataset

parser = argparse.ArgumentParser()
parser.add_argument("--base", required=True)
parser.add_argument("--data", required=True)
parser.add_argument("--out", required=True)
parser.add_argument("--batch_size", type=int, default=4)
parser.add_argument("--epochs", type=int, default=3)
parser.add_argument("--lr", type=float, default=2e-4)
parser.add_argument("--lora_r", type=int, default=16)
parser.add_argument("--lora_alpha", type=int, default=16)
parser.add_argument("--dropout", type=float, default=0.1)
parser.add_argument("--quatization", choices=["none","q4_0","q4_1"], default="none")
args = parser.parse_args()

# Tokenizer & model (with 4-bit if requested)
bnb_config = None
if args.quatization != "none":
    from transformers import BitsAndBytesConfig
    bnb_config = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_compute_dtype=torch.bfloat16,
    )

tokenizer = AutoTokenizer.from_pretrained(args.base)
model = AutoModelForCausalLM.from_pretrained(
    args.base,
    quantization_config=bnb_config,
    device_map="auto"
)
model.config.use_cache = False

# LoRA setup
lora_cfg = LoraConfig(
    task_type="CAUSAL_LM", r=args.lora_r,
    lora_alpha=args.lora_alpha,
    lora_dropout=args.dropout,
    target_modules=["q_proj","k_proj","v_proj","o_proj"]
)
model = get_peft_model(model, lora_cfg)

# Dataset loading
raw = load_dataset("json", data_files=args.data)["train"]
def preprocess(x):
    return tokenizer(x["prompt"] + x["completion"], truncation=True)
dataset = raw.map(preprocess, batched=True)

# Trainer
training_args = TrainingArguments(
    output_dir=args.out,
    per_device_train_batch_size=args.batch_size,
    num_train_epochs=args.epochs,
    learning_rate=args.lr,
    fp16=True,
    logging_steps=10,
    save_strategy="no"
)
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    tokenizer=tokenizer,
)
trainer.train()
model.save_pretrained(os.path.join(args.out, "lora_adapter"))
tokenizer.save_pretrained(os.path.join(args.out, "lora_adapter"))
```

### GGUF Merge & Quantize (`merge_quantize.py`)

```python
import subprocess, argparse
parser = argparse.ArgumentParser()
parser.add_argument("--base_fp16", required=True)
parser.add_argument("--lora_adapter", required=True)
parser.add_argument("--out_gguf", required=True)
parser.add_argument("--quant_bits", type=int, choices=[2,4,8], default=4)
args = parser.parse_args()

# Convert HF → GGUF FP16
subprocess.run([
    "python3", "convert_hf_to_gguf.py",
    "--outfile", args.base_fp16.replace(".gguf","-f16.gguf"),
    args.base_fp16
], check=True)

# Convert LoRA → GGUF
subprocess.run([
    "python3", "convert_lora_to_gguf.py",
    "--base", args.base_fp16,
    "--outfile", "lora-adapter.gguf",
    args.lora_adapter
], check=True)

# Merge
subprocess.run([
    "./llama.cpp/bin/llama-export-lora",
    "-m", args.base_fp16.replace(".gguf","-f16.gguf"),
    "--lora", "lora-adapter.gguf",
    "-o", "merged-f16.gguf"
], check=True)

# Quantize to Q4_0
subprocess.run([
    "./llama.cpp/bin/llama-quantize",
    "merged-f16.gguf",
    args.out_gguf,
    str(args.quant_bits)
], check=True)
```

## Data Format & Storage

* **Uploaded JSONL** (`data/raw/*.jsonl`):

  ```json
  {"prompt":"<|system|>…<|eot|>","completion":"…<|eot|>"}
  ```
* **Corpus JSONL** (`data/corpus/*.jsonl`): final `{"prompt":…,"completion":…}` pairs for training.
* **Metadata** stored in SQLite via Prisma: tracks job status, timestamps, presets.

## End-to-End Workflow

1. **Pull Model**:

   * Click → `POST /api/models/pull` → BullMQ job → `ollama pull llama3.1:8b-instruct-q4_0`
2. **Upload Data**:

   * Drag/drop JSONL → client AJV → `POST /api/data/upload` → saved under `data/raw/`
3. **Configure & Train**:

   * Fill hyperparameters → `POST /api/jobs/train` → queued
   * Worker runs `train.py` → `merge_quantize.py` → `ollama create custom-<id>`
4. **Monitor**:

   * Real-time logs via Socket.IO → LogsViewer
   * GPU stats polled every 2 s → header widget
   * Toasts on start/complete/fail
5. **Test**:

   * Enter prompt → `POST /api/jobs/:id/test` → streams `ollama run custom-<id>` output

## Error Handling & Logging

* **Structured Logs** with Winston (timestamp, level, message).
* **API Errors** return `{ error: "...", code: 400/500 }`.
* **Worker Failures**: caught, logged, status updated in DB, client notified via Socket.IO.
* **Early-Stop**: Worker monitors loss/timeout and terminates gracefully with status `cancelled`.

## Security & Isolation

* **Docker** for Python scripts to sandbox arbitrary code (avoid host contamination).
* **CORS** restricted to your dev domain.
* **Rate-Limit** heavy endpoints (uploads, train requests).
* **Validate** all user inputs (AJV, Zod) to avoid injection.

## Troubleshooting

* **“CUDA out of memory”** → lower batch size, use Q4\_0 quantization, free VRAM via `nvidia-smi`.
* **“AJV validation failed”** → check JSONL schema, view inline error tooltip.
* **“Ollama CLI not found”** → ensure `ollama` in PATH, `brew install ollama` or `ollama self-update`.
* **Slow startup** → pre-pull base models and cache in `~/.ollama/models`.
